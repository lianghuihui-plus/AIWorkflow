# 代码实现

## 要解决的问题

在当前任务范围内把已批准规格落实到真实代码仓库，并留下能够解释实际改动与验证结果的实现报告。

## 建议关注

- 先理解仓库现有结构、约定、相关代码和任务开始前已有差异。
- 实现关键行为、异常路径、兼容边界和必要的可观测性。
- 复用现有模式，控制修改范围，保护无关及用户已有改动。
- 执行与风险相称的编译、静态检查或定向测试。
- 记录与规格不一致之处及原因，不把实际偏离隐藏在文件清单中。

## 最低交付内容

报告必须覆盖实际修改、关键实现决策、与规格的差异、已执行验证、未解决问题和风险。结果清单登记本任务实际触碰的文件及验证摘要。

## 必须停止的情况

只有实现必须改变已批准需求、整体设计、公开兼容承诺，或可能覆盖无法归属的既有改动时才提交阻塞问题。局部且可逆的技术选择由 Agent 按仓库事实完成。
