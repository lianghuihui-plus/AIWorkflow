# 任务规格

## 要解决的问题

将当前任务的已确认设计收敛为足以直接指导实现的规格，同时保持任务边界和上游可追溯性。

## 建议关注

- 当前任务关联的需求、设计决策和前置任务。
- 预期行为、异常行为、兼容行为和不在本任务内的内容。
- 预计影响的模块、数据、接口和关键实现约束。
- 与现有代码模式的结合点及可能的实现风险。

只描述当前任务。不要复制整份设计，也不要为后续测试阶段预先生成测试代码模板。

## 最低交付内容

产物必须覆盖任务目标、关联需求和设计决策、前置依赖、预期行为与边界、实现思路和预计修改范围。

## 必须停止的情况

只有当前任务无法在既定设计边界内确定行为，或继续会迫使 Agent 改变已批准需求或设计时才提交阻塞问题。普通实现细节和可逆技术选择不阻塞规格生成。
