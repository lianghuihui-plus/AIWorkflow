# 产物契约：output/test-reports/T-XXX.md

## 路径

`output/test-reports/T-XXX.md`

## 必需章节

- `# 单元测试报告 — T-XXX {任务标题}`
- `## 审核状态`
- `## 任务范围`
- `## 已生成单元测试`
- `## 未生成单元测试`
- `## 辅助验证记录`
- `## 结论`

## 已生成单元测试

`## 审核状态` 必须符合 `contracts/review-status.md`。新生成或修订后的测试报告状态必须为 `待审核`；只有用户确认后才能改为 `已确认` 并标记对应任务测试完成。

测试报告的长文本记录不得使用横向 Markdown 表格。`行为`、`测试点`、`说明`、`命令/方式` 等字段容易包含长句、代码片段或路径时，必须按条目使用列表块，避免在 `dashboard.html` 中形成过宽表格或窄列竖排文字。

```markdown
### 1. {简短测试项标题}

- **行为：** {规格/实现行为}
- **测试点：** {断言点或覆盖点}
- **测试文件：** `tests/Xxx.test.ts`
- **状态：** 已生成
- **说明：** {补充说明}
```

## 未生成单元测试

全部覆盖时写一句结论，不写占位表格：

```markdown
全部目标行为已生成单元测试。
```

存在暂未生成单元测试的行为时：

```markdown
### 1. {简短未覆盖项标题}

- **行为：** {规格/实现行为}
- **测试点：** {期望覆盖点}
- **测试文件：** —
- **状态：** 不适用/阻塞/待补充
- **说明：** {原因和后续条件}
```

## 辅助验证记录

未执行验证时写一句结论，不写占位表格：

```markdown
未执行辅助验证：{原因}。
```

存在验证记录时：

```markdown
### 1. {验证项}

- **命令/方式：** `<wf-skill-dir>/scripts/test-runners/{platform}/run-unit.sh`
- **结果：** 通过/失败/未执行
- **说明：** {摘要或日志路径}
```

## 编号规则

- `已生成单元测试`、`未生成单元测试` 和 `辅助验证记录` 的真实条目序号从 1 开始递增，并按覆盖行为、规格行为或执行顺序稳定排列。
- 新增真实条目时追加到对应章节末尾，并使用下一个序号；不要插到已有条目顶部。
- 没有未生成单元测试或没有辅助验证记录时，使用一句结论说明，不写 `—` 占位表格。
- 只有字段非常短且不会包含行为说明、路径、命令或补充说明时，才允许使用 Markdown 表格；测试项明细默认使用列表块。

## 质量规则

- 覆盖规格中的正常路径、边界条件、异常路径和状态变化。
- 审核状态必须存在，且标记测试完成前必须为 `已确认`。
- 遵循现有测试框架和目录模式。
- 缺少本报告时，不得在 `CONTEXT.md` 中标记测试完成。
- 如果行为不明确导致无法安全编写测试，必须写入测试阶段问题。
- 单元测试生成环节默认只修改测试代码和测试报告；需要调整业务逻辑代码时必须写入问题或转入实现修订流程。
- 辅助验证记录只作为执行追溯，不替代单元测试覆盖。
- 存在 `阻塞`、`待补充` 或 `已生成，未通过` 状态时，测试报告不得审核为 `已确认`；应保持 `待审核` 或 `需修改`，并通过修订或决策流程收敛。
